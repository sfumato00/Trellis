# Repository Package Map

These guidelines describe the current Trellis repository shape and how package
keys in `.trellis/config.yaml` map to source code and specs.

## Purpose

Keep Trellis package/spec routing aligned with the actual repository so
`get_context.py --mode packages`, task package binding, and future AI sessions
load the right guidance.

## Package Map

| Package key | Path | Package name | Spec path | Purpose |
| --- | --- | --- | --- | --- |
| `cli` | `packages/cli` | `@mindfoldhq/trellis` | `.trellis/spec/cli/**` | User-facing CLI, templates, migrations, release scripts, and platform configurators. |
| `core` | `packages/core` | `@mindfoldhq/trellis-core` | `.trellis/spec/core/**` | Reusable SDK/domain primitives for channel, mem, task, and testing APIs. |
| `docs-site` | `docs-site` | `trellis-docs` | `.trellis/spec/docs-site/**` | Mintlify documentation site. This directory is a git submodule, not part of `pnpm-workspace.yaml`. |

## Workspace And Submodules

- `pnpm-workspace.yaml` declares `packages/*`, so the pnpm workspace packages
  are `packages/cli` and `packages/core`.
- `.gitmodules` declares `docs-site` and `marketplace` as submodules.
- `docs-site` has its own package manifest and Trellis specs, so it is a
  configured Trellis package with `type: submodule`.
- `marketplace` is a submodule but currently has no package manifest and no
  Trellis package-scoped specs. Do not add it to `.trellis/config.yaml` unless
  it gains package-level implementation ownership or specs.

## Non-Package Docs: `docs/explainer/`

`docs/explainer/index.html` is a self-contained, bilingual (en/zh) diagram page
that explains to new contributors what problem Trellis solves and how the repo is
built. It is not part of any package, build, test, or npm tarball.

- It restates facts that live elsewhere: the `AI_TOOLS` count (22), the sub-agent
  context classes in `cli/backend/platform-integration.md` (9 / 7 / 2, plus 3
  command-only and 1 skills-first), the `@mindfoldhq/trellis-core` subpath
  exports, the migration manifest count, and the template → configurator →
  repo pipeline. When one of those changes, update the page and its footer
  version line.
- Both languages sit side by side as `[lang="en"]` / `[lang="zh"]` sibling
  pairs (SVG labels use `<tspan>` pairs); CSS shows one. Language-neutral text
  is marked `data-neutral` or lives in `<code>`.
- Icons come only from the `<symbol>` sprite at the top of the file.
- It follows the Artifact page contract (no `<!doctype>`/`<html>`/`<body>`),
  so opening the file directly renders in quirks mode; the published copy
  renders in standards mode. Both were checked.
- Check after editing (fails on external resources, duplicate ids, missing
  icons, unpaired or untranslated text):

```bash
node docs/explainer/verify.mjs docs/explainer/index.html
```

## Contracts

- `.trellis/config.yaml` uses stable Trellis package keys (`cli`, `core`,
  `docs-site`) rather than npm package names. These keys are part of spec paths
  and task package bindings.
- `default_package` is `cli`; new tasks without `--package` bind to CLI because
  most Trellis workflow/runtime changes are CLI-owned.
- Existing tasks keep their frozen `task.json.package`. Changing
  `.trellis/config.yaml` does not retroactively rebind old tasks.
- Package-context output is generated by
  `.trellis/scripts/common/packages_context.py`, which scans
  `.trellis/spec/<package>/<layer>/index.md` for each configured package.

## Checks

```bash
python3 ./.trellis/scripts/get_context.py --mode packages
python3 "${CODEX_HOME:-$HOME/.codex}/skills/trellis-spec-maintainer/scripts/scan_spec_drift.py"
git diff --check -- .trellis/config.yaml .trellis/spec
```

If a future checkout provides a package-map checker under the Trellis scripts
directory, run it as part of package-map validation. That helper is not
currently present in this repo.
