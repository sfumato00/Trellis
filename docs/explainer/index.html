Why Trellis exists, and how it is builtTrellis 为什么存在，又是怎么搭起来的

AI coding agents forget. Each session starts cold, long chats get compacted, and every tool wants its own setup. Trellis keeps a project's rules, plans and memory in files inside the repo, and hands the right slice of them to 22 AI tools at the right moment.AI 编码智能体会遗忘：每次会话都从零开始，长对话会被压缩，每种工具还各要一套配置。Trellis 把项目的规范、计划和记忆存成仓库里的文件，并在合适的时机，把合适的那一部分交给 22 种 AI 工具。

Solution · workflow解法 · 工作流

Every piece of work is a task that moves through three phases, and approval to plan is not approval to code每项工作都是一个任务，按三个阶段推进；同意规划不等于同意写代码

The task directory is where decisions survive compaction. task.py start is the gate between planning and code, and it refuses to run while the context lists are empty.任务目录是决策扛过上下文压缩的地方。task.py start 是规划和写代码之间的关卡：上下文清单还空着时，它会拒绝执行。

What each file in a task directory holds任务目录里每个文件放什么
  • task.json · status, branch, parent/child links状态、分支、父子任务关系
  • prd.md · requirements and acceptance criteria only只写需求和验收标准
  • design.md · boundaries, contracts, data flow, tradeoffs边界、契约、数据流、取舍
  • implement.md · ordered checklist, validation commands, rollback points有序清单、验证命令、回滚点
  • implement.jsonl / check.jsonl · spec and research files the sub-agents receive子智能体会收到的规范与调研文件
  • research/ · findings persisted by trellis-researchtrellis-research 落盘的调研结果

Solution · injection解法 · 注入

Context arrives at three moments, each kept small, and the rest is loaded on demand上下文在三个时刻送达，每次都尽量精简，其余内容按需加载

Large payloads used to hit host truncation, so SessionStart now sends orientation and paths, not whole documents. Step details come from get_context.py --mode phase --step X.Y when the agent needs them.过去注入的内容太大，会被宿主截断。所以现在 SessionStart 只送方位信息和路径，不送整篇文档。某一步的细节，等智能体需要时再通过 get_context.py --mode phase --step X.Y 加载。

Architecture · packages架构 · 包

Two packages: core holds reusable domain logic, the CLI owns everything a terminal user touches两个包：core 放可复用的领域逻辑，CLI 负责终端用户接触到的一切

Both versions are locked together. The CLI depends on core through workspace:*, so core must be built before you typecheck or test the CLI.两个包的版本号锁定一致。CLI 通过 workspace:* 依赖 core，所以对 CLI 做类型检查或测试之前，必须先构建 core。

Architecture · distribution架构 · 分发

Templates are the only source. Every .claude/ or .trellis/ at a repo root is generated output, including in this repo模板是唯一的源头。仓库根目录下的 .claude/、.trellis/ 都是生成物，本仓库也不例外

This is the trap new contributors fall into most often. Trellis is installed into itself, so the root folders look like source, but editing them changes nothing that ships.这是新贡献者最常踩的坑。Trellis 把自己安装进了自己的仓库，根目录这些文件夹看起来像源码，但改了它们，发布出去的东西一点都不会变。

Change shipped behavior in packages/cli/src/templates/, then run trellis update to refresh this repo's own copy.要改发布出去的行为，就改 packages/cli/src/templates/，再运行 trellis update 刷新本仓库自己的那份副本。
Don't hand-edit root .claude/, .cursor/, .trellis/ (except this repo's own spec/ and tasks), packages/cli/dist/ or .trellis/.backup-*.不要手改根目录的 .claude/、.cursor/、.trellis/（本仓库自己的 spec/ 和任务除外），也不要手改 packages/cli/dist/ 或 .trellis/.backup-*。
Editing a .trellis/scripts/**/*.py? Make the same edit in the template twin. test/regression.test.ts fails if they differ by a single byte.要改 .trellis/scripts/**/*.py？模板里的那份也要做同样的修改。两者只要差一个字节，test/regression.test.ts 就会失败。

Architecture · update架构 · 更新

trellis update upgrades every file you never touched and protects every file you editedtrellis update 会升级你没动过的每个文件，并保护你改过的每个文件

The hash file records exactly what Trellis installed. If a file still matches it, the file is safe to replace. If not, it's yours.哈希文件准确记录了 Trellis 安装时写入的内容。文件与记录一致，就可以放心替换；不一致，就说明是你改过的。

Three files follow special rules三个文件有特殊规则
  • AGENTS.md · only the region between <!-- TRELLIS:START --> and <!-- TRELLIS:END --> is merged. Your text outside it is left alone.只合并 <!-- TRELLIS:START --> 与 <!-- TRELLIS:END --> 之间的区域，区域外你写的内容不会被动。
  • .trellis/workflow.md · updated as one whole file, never block by block, because scripts parse its phase and platform sections.只能整文件更新，不能按块更新，因为脚本会解析其中的阶段和平台段落。
  • .template-hashes.json · written atomically (temp file, then rename), so a crash can't make every file look user-modified.原子写入（先写临时文件，再重命名），程序崩溃也不会让所有文件都被误判为用户改过。
